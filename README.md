# chickinfry

Native Rust runtime for Chickinfry. Generated Rust servers and client SDKs
build on this crate instead of reimplementing the HTTP transport, session
handling, database access, and ORM execution.

## Status

Rust support is in development and is not yet listed as supported; it will be
marked supported once verification is complete.

## Installation

This crate is not published to crates.io yet. Rust projects generated by the
Chickinfry CLI depend on it automatically; installation instructions will be
added here once the crate is published.

## First call

The HTTP client is available on native targets. Each operation call is one
JSON request to `POST {origin}/{service.operation}`; origins must be HTTPS,
or loopback HTTP for local development.

```rust
use chickinfry::client::Client;

fn main() -> Result<(), chickinfry::client::ClientError> {
    // The generated client builds its typed methods on this transport.
    let transport = Client::new("https://your-project.chickinfry.app")?;
    let response = transport.invoke(
        "notes.list",
        &chickinfry::serde_json::json!({ "limit": 10 }),
    )?;
    println!("{response}");
    Ok(())
}
```

The generated client exposes the same call as a typed method for every
declared operation, so you pass a typed input struct and get a typed output
struct back.

`client::MemorySessionStore` keeps an optional session record for one origin in
memory. Its `clear(expected)` compares and deletes under the same lock, so a
late rejection cannot remove a newer login. Custom `client::SessionStore`
implementations must also make this comparison and deletion atomic.
Refresh compares the original record before saving a successful response and
preserves concurrent replacement or deletion. Custom stores must do the same,
without holding a storage lock during network activity.
